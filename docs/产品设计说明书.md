---

## 1. 产品定位与建设背景

### 1.1 背景
企业对 Windows Server Active Directory（AD）的日常运维高度依赖图形化工具（ADUC、PowerShell），存在以下痛点：

- 运维人员分散、权限无法精细化收敛，域管理员账号常被滥用；
- 批量开户/禁用/改密依赖手工脚本，易出错、难审计；
- 缺乏统一的操作留痕，出现误删、越权操作时无法追溯；
- 多分支机构、多域林场景缺少统一的跨域管理入口。

### 1.2 产品定位
DomainToolBS 是一套**集中式、基于 B/S 架构的 AD 域管理控制台**，提供：

- 域控连接配置与连通性测试；
- 组织单元（OU）、域用户、用户组、计算机账号的全生命周期管理；
- 批量导入/导出、批量删除、批量修改；
- 多域、四角色、范围化授权的权限体系；
- 完整审计日志。

## 2. 目标用户与角色

| 角色 | 标识 | 能力范围 |
|---|---|---|
| 超级管理员 | `super_admin` | 平台最高权限；管理所有域、所有账户、授权矩阵、审计；自身账号只能通过服务器侧维护 |
| 管理员 | `admin` | 在授权域范围内（含自建域自动授权）进行写操作；可新建域 |
| 普通用户 | `user` | 全部域的**只读**访问；查看域配置时连接凭据脱敏；无写/授权/审计权限 |
| 审计员 | `auditor` | 仅可查看/导出审计日志，无目录访问与任何写权限 |

> 读接口（GET 类查询）按角色 + 域可见性约束，**不纳入作用域授权**；写/删类接口受「域 + OU + 权限」三重作用域约束。
> **作用域授权仅适用于 `admin` 角色**：`user`/`auditor` 为系统内置默认权限（普通用户=全域只读、审计员=仅审计），无需也不能在「授权管理」中配置作用域。

## 3. 功能范围

### 3.1 域配置管理（多域）
- 多域控条目 CRUD（名称、域控地址、LDAPS 端口、Base DN、绑定账号/密码、说明）；
- 连通性测试（`/domains/test`）与域信息概览（`/domains/{id}/info`）；
- **管理员可新建域**：同名或同 Base DN 视为重复，自动拒绝并提示由超管分配；管理员自建的域**自动获得该域整域全写权限**；
- 普通用户查看域列表时，敏感字段（host、bind_dn）脱敏。
- **CA 认证总开关（仅超级管理员）**：每个域可独立开启/关闭 CA 认证（`ca_enabled`，默认开启）。
  - **开启**：与现状一致——平台按域控证书信任状态（`cert_trust`）校验，证书未通过（缺 CA / 已过期 / 校验失败）时暂停非超级管理员的写操作；
  - **关闭**：不启用任何 CA 相关限制，管理员可自由操作，后台每日巡检也不再对该域产生证书告警；
  - 开关权限仅限超级管理员；管理员/普通用户即使看到域配置，也无法切换该开关。

### 3.2 组织与用户
- OU 树浏览、子 OU 新建/删除；
- 域用户列表（支持按 OU 归属、关键字、启用/禁用、锁定过滤）；
- 用户 CRUD、启用/禁用、重置密码（可强制下次登录修改）、解锁、移动到其他 OU；
- 用户详情信息查看。

### 3.3 用户组
- 用户组列表与成员管理（分片分页，适配大集团场景）。

### 3.4 计算机
- 计算机账号列表（支持按 OU 归属、关键字、启用/禁用过滤）；
- 启用/禁用、移动到 OU、删除。

### 3.5 批量任务
| 类型 | 说明 | CSV 字段 |
|---|---|---|
| 批量新增用户 | 按模板导入并创建用户 | sAMAccountName、displayName、password、userPrincipalName、mail、department、title、telephoneNumber、description、password_never_expires、must_change_next_logon、ou_dn |
| 批量删除用户 | 按登录名批量删除 | sAMAccountName |
| 批量修改用户 | 批量改属性/密码/启用状态 | sAMAccountName + 可选 displayName/mail/department/title/telephoneNumber/description/password/must_change_next_logon/enabled |
| 批量导出 | 当前域用户导出为 CSV | — |

- 所有批量任务异步执行（FastAPI `BackgroundTasks`），逐行做作用域校验，单行失败不中断整体，结果可在「批量任务」明细查看成功/失败与原因。

### 3.6 审计日志
- 记录范围：**域对象（用户 / 用户组 / 计算机 / OU）的写操作**（创建、更新、删除、启用/禁用、移动 OU、解锁、重置密码、组成员增删）+ **批量任务**；
- 每条记录含操作人、动作、目标 DN/名称、域、操作 IP、参数、结果（ok/fail 及错误原因）；
- 支持按域、动作、时间过滤与导出；
- **不记录**以下行为（当前版本设计如此，非缺陷）：平台账号的登录、平台账号自身密码修改、平台账号（超管/管理员/用户/审计员）的增删改、授权(scope)变更。如需此类审计可后续扩展。

### 3.7 授权管理（范围化，仅超管）
- 权限矩阵：`user:write/user:delete/user:reset_password`、`group:write/group:delete`、`computer:write/computer:delete`、`ou:write`；
- 委派管理员作用域 = 域（`domain_id`）+ OU 子树（`base_dn`）+ 权限集合；支持多条作用域取并集；
- 超级管理员不可被配置作用域。

### 3.8 账户管理（仅超管）
- 平台登录账号 CRUD（`admin/user/auditor`）；
- **禁止通过界面创建/编辑/删除/设为超级管理员**，禁止删除自身；
- 超管账号只能通过服务器侧脚本维护（见部署/运维文档）。

### 3.9 密码与登录
- 首次部署通过「初始化平台」引导创建超管（`/auth/bootstrap`）；
- 登录使用 JWT（默认 120 分钟过期）；
- **密码复杂度策略**：长度 ≥ 8，且须同时包含大写字母、小写字母、数字、符号（如 `!@#$%^&*`）。适用于初始化、超管创建/编辑账号、重置密码、用户自行改密；
- **密码历史策略**：修改/重置密码不得与当前密码相同，也不得与**最近 3 次**使用过的密码相同（历史仅保留旧密码哈希，最多 3 条）；
- 任意登录用户可在 Web 端修改自身密码（`/auth/change-password`），受上述复杂度 + 历史约束；
- 超管密码遗忘只能在服务器侧用脚本重置。

## 4. 关键业务流程

### 4.1 首次部署引导
```
部署启动 → 访问前端 → 若无任何账号 → 引导创建超级管理员(bootstrap)
→ 进入「域配置」填写域控并连通性测试 → 开始日常运维
```

### 4.2 管理员新建域并获权
```
管理员进入「域配置」→ 新建域（填名称/地址/BaseDN/绑定账号）
→ 后端查重（name 或 base_dn）→ 不存在则创建
→ 自动插入 AdminScope(该管理员, 该域, 整域, 全部写权限)
→ 该域立即出现在管理员的可管理域列表中
```

### 4.3 作用域校验（写操作）
```
请求到达写接口 → get_current_admin 解析 JWT
→ get_domain_config 校验域可见性/管辖
→ check_scope(admin, action, domain_id, target_dn, db)
   ├─ 超管 → 放行
   └─ 普通管理员 → 需存在授权域且 target_dn 位于 base_dn 子树且含该 action
```

### 4.4 批量任务
```
上传 CSV → 后端校验表头/数据 → 建 BatchTask + 行级 BatchTaskItem
→ 后台 worker 逐行：定位 DN → 作用域校验 → 执行 AD 操作 → 更新行状态
→ 前端轮询/查看任务明细
```

## 5. 技术架构

### 5.1 总体架构
```
浏览器(Vue3 + Element Plus)
        │ HTTPS
        ▼
Nginx(前端静态 + /api 反代)
        │
        ▼
FastAPI 后端  ── LDAP(S) ──► Windows Server AD
        │
        ▼
本地数据库(PostgreSQL 生产 / SQLite 开发)
```

### 5.2 技术栈
| 层 | 选型 |
|---|---|
| 后端 | FastAPI + ldap3 + SQLAlchemy 2.x + PyJWT + bcrypt + cryptography(Fernet) |
| 前端 | Vue3 + Vite + TypeScript + Element Plus + Pinia + Axios |
| 本地库 | 开发 SQLite / 生产 PostgreSQL 16 |
| 域对接 | Windows Server AD，LDAPS(636) + ldap3 |
| 部署 | Docker Compose（后端 uvicorn、前端 nginx） |

### 5.3 关键设计点
- **两类凭据分离**：平台登录用本地账号（`admin_user`，bcrypt 哈希）；后端连接 AD 用独立域服务账号（`domain_config`，Fernet 加密存储），互不相干。
- **DN 编码**：OU/用户的 DN 含逗号与等号，URL 路径参数统一用 URL-safe Base64 编码（后端 `core/dn.py` ↔ 前端 `utils/dn.ts`）。
- **作用域授权**：`admin_scope` 表存储「域 + OU + 权限」，写前统一走 `core/deps.check_scope`。
- **AD 写操作必须走 LDAPS**：`unicodePwd` 需 UTF-16LE + 双引号；解锁写 `lockoutTime=0`（非 userAccountControl）。

### 5.4 数据模型（本地库）
`admin_user`（含 role/is_superuser）、`admin_scope`、`domain_config`、`audit_log`、`batch_task`、`batch_task_item`。

## 6. 安全设计

1. **最小权限**：域服务账号不要使用 Domain Administrator，用 AD「委派控制向导」仅授予目标 OU 的创建/删除用户、重置密码、读写属性等权限。
2. **密钥隔离**：`JWT_SECRET_KEY`、`FERNET_KEY` 必须显式配置，否则重启后旧凭据密文无法解密。
3. **传输安全**：AD 写操作强制 LDAPS；平台建议 HTTPS 反向代理。**注意**：当前连接 AD 使用 `Tls(validate=ssl.CERT_NONE)`，即**不校验域控证书**（自签名证书可直接连通），但存在中间人风险；生产环境建议由边界反代或域控侧配置可信证书，并知悉该取舍。域的「CA 认证开关」关闭时，平台完全不对该域做证书校验与写操作限制（仅建议在可信隔离内网 / 测试域使用）。
4. **密码策略**：复杂度（≥8 位含大小写/数字/符号）+ 历史（不可复用当前及最近 3 次），详见 3.9。
5. **审计范围**：仅覆盖域对象写操作与批量任务，详见 3.6（登录、账号管理、授权变更、自身改密不记录）。
4. **超管约束**：超管账号不可经 Web 增删，杜绝界面越权。
5. **审计留痕**：所有敏感操作落库可溯。

## 7. 非功能性需求

- **兼容性**：对接 Windows Server 2012R2 及以上 AD；前端现代浏览器（Chrome/Edge/Firefox）。
- **性能**：用户/计算机列表分页（默认 20/页），OU 树懒加载，批量任务异步化。
- **可扩展性**：权限矩阵可横向扩展资源×操作；多域架构支持跨域林。

## 8. 版本与路线图

- P0–P5：骨架、本地登录、超管自举、域配置、OU 树、用户/组/计算机 CRUD、批量导入导出、审计、委派授权界面。
- **P6（本版）**：多域 + 四角色体系；管理员可新建域（重复校验 + 自动授权）；批量删除/修改；用户/计算机 OU 归属查询；超管密码服务端找回；P6-6 测试。
- **v1.1 增量**：① 域控「CA 认证总开关」（仅超级管理员），关闭后该域不启用任何 CA 限制、管理员可自由操作；② 补齐 OU 创建/更新/删除/移动的审计日志（此前 OU 写操作完全未留痕）。
