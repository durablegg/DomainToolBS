## 1. 架构与部署拓扑

| 组件 | 技术 | 说明 |
|---|---|---|
| 前端 | Vue3 + nginx（容器内 80） | `docker-compose.yml` 映射 `8080:80` |
| 后端 | FastAPI + uvicorn（容器内 8000） | 映射 `8000:8000`，实际经 nginx 反代，外部只暴露 8080 |
| 数据库 | PostgreSQL 16（容器内） | 仅容器内通信，不对外暴露；数据持久化在 `pgdata` 卷 |
| 编排 | docker-compose | `db` / `backend` / `frontend` 三个服务 |

- 浏览器访问：`http://<平台服务器IP>:8080`，nginx 把 `/api/` 反代到 `backend:8000`，因此后端 API 与前端同源，跨域基本不触发。
- 平台通过 LDAP(S) 去连**各分公司的域控**（AD）执行用户/计算机/组/OU 操作。

## 2. 平台服务器前置准备（Docker）

平台服务器可以是任意能装 Docker 的 Linux（本手册以 Ubuntu 为例）。

### 2.1 安装 Docker

国内服务器访问 `download.docker.com` 常被重置，推荐用 Ubuntu 自带源或阿里云镜像：

```bash
# 方式一：Ubuntu 自带源（apt 走国内镜像即可）
sudo apt update
sudo apt install -y docker.io docker-compose-v2

# 方式二：官方脚本 + 阿里云镜像
curl -fsSL https://get.docker.com | sudo sh -s -- --mirror Aliyun
```

启动并设置开机自启，把当前用户加入 docker 组（免 sudo，需重登生效）：

```bash
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
# 退出 SSH 重新登录后 docker 命令不再需要 sudo
```

> 未加入 docker 组时所有 `docker` 命令需加 `sudo`，否则报 `permission denied ... /var/run/docker.sock`。

### 2.2 配置镜像加速器（拉取镜像用）

apt 源只是装 Docker 软件；部署时要从 Docker Hub 拉 `postgres:16`、`python:3.13-slim`、`node:20-alpine`、`nginx:alpine`，国内网络常连不上。配置加速：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://hub.rat.dev"
  ]
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
```

验证加速器可用：

```bash
docker run --rm hello-world
# 出现 "Hello from Docker!" 即成功
```

## 3. 上传源码并启动平台

### 3.1 本地打包（Windows PowerShell，项目根目录）

排除虚拟环境、依赖、IDE 配置、本地密钥和数据库：

```powershell
cd D:\PycharmProjects\DomainToolBS
tar -czf deploy.tar.gz `
  --exclude='.venv' --exclude='node_modules' --exclude='.idea' `
  --exclude='__pycache__' --exclude='*.pyc' --exclude='*.db' `
  --exclude='.git' --exclude='backend/.env' .
```

> **不要传 `backend/.env`**：那是本地开发密钥，服务器单独生成。

### 3.2 上传到服务器

`/opt` 默认 root 所有，普通用户可能无写权限。建议先传到家目录再移动：

```powershell
scp deploy.tar.gz user@<平台服务器IP>:~/
```

服务器侧：

```bash
sudo mkdir -p /opt/DomainToolBS
sudo chown $USER:$USER /opt/DomainToolBS
mv ~/deploy.tar.gz /opt/DomainToolBS/
cd /opt/DomainToolBS
tar -xzf deploy.tar.gz && rm -f deploy.tar.gz
```

### 3.3 生成生产环境 `.env`（关键）

compose 用同目录 `.env` 注入 `JWT_SECRET_KEY` / `FERNET_KEY` / `CORS_ORIGINS`。
**`FERNET_KEY` 必须生成**，否则域账号密码加密/解密会失败。

```bash
cd /opt/DomainToolBS
cat > .env <<EOF
JWT_SECRET_KEY=$(openssl rand -hex 32)
FERNET_KEY=$(python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())")
CORS_ORIGINS=http://<平台服务器IP>:8080
EOF
cat .env        # 确认 FERNET_KEY 一行不为空
```

### 3.4 构建并启动

```bash
cd /opt/DomainToolBS
docker compose up -d --build
```

首次会拉 4 个基础镜像 + 装 pip/npm 依赖，耗时数分钟，勿中断。

### 3.5 验证

```bash
docker compose ps            # 三个服务都应 Up/healthy
docker compose logs --tail 50 backend   # 看是否有报错（期望 "Application startup complete"）
```

后端容器启动会自动跑 `init_db()` → `_migrate()`，自动建表并加新列（如 `ca_enabled`、`audit_log.domain_id`），**首次部署无需手动建库**。

## 4. 首次访问与初始化超管

1. 浏览器打开 `http://<平台服务器IP>:8080`。
2. 防火墙放行 8080（若启用 ufw）：`sudo ufw allow 8080/tcp`。
3. 登录页点「**首次使用？初始化平台**」，创建**超级管理员**账号（自动登录）。
   - 这是 bootstrap 流程，数据库里一旦有任何管理员就不可再用（防止被滥用）。
   - 超管密码忘记用服务器运维脚本 `backend/scripts/reset_superadmin.py` 重置，**不是**走这个入口。
4. 建议开启容器自启：在 `docker-compose.yml` 各服务下加 `restart: unless-stopped`，或 `sudo systemctl enable docker`。

## 5. 域控 LDAPS 配置（关键，必读）

### 5.1 为什么必须用 636（SSL）

AD 的硬性规则：**修改 `unicodePwd`（设/改密码、重置密码）必须在加密通道上进行**（LDAPS 636 或 StartTLS）。明文 LDAP（389）连接能 bind、能查询，但**创建用户 / 改密码会失败**（对象建出来却设不上密码，平台会报“创建成功但报错”）。

### 5.2 启用 LDAPS 的完整步骤（每个分公司独立域都要各自做）

> ⚠️ 关键经验：**必须先安装 AD CS 角色，否则申请证书时不会出现“域控制器”模板。**

#### 步骤 1：安装 AD 证书服务（AD CS）— 每个独立域各自需要

1. B/C/D 是独立域，证书必须**本域的企业 CA** 签发（A 的 CA 管不到其他域）。
2. 在该域的一台服务器（可以是域控本身）上：服务器管理器 → 添加角色和功能 → 勾选 **Active Directory 证书服务** → 角色服务勾选「证书颁发机构」→ 配置为**企业根 CA**。
3. 安装完**重启**该服务器。

#### 步骤 2：为域控申请“域控制器”证书

1. 在**目标域控**上 `certlm.msc`（本地计算机证书）。
2. 个人 → 所有任务 → **申请新证书** → 策略选「Active Directory 注册策略」。
3. 此时应能看到 **「域控制器」模板**（装了 AD CS 后才出现），勾选并注册。
4. 确认证书：
   - 出现在「个人」存储；
   - 有**私钥**（钥匙图标 / “您有与此证书对应的私钥”）；
   - **预期目的 = 服务器身份验证**；
   - **颁发给 = 该域控自己的 FQDN**。

> 若自动注册没出现该模板，也可选「计算机」模板申请，效果相同（只要含服务器身份验证 EKU）。

#### 步骤 3：重启 NTDS 使证书生效

证书到位后 DC 需重新加载才能监听 636。

```cmd
:: 注意：Windows PowerShell 5.1 不支持 &&，需分开执行
net stop ntds
:: 提示是否停止，输入 Y
net start ntds
```

> `net stop ntds` 会短暂把该 DC 下线（连带 KDC/DNS/DFS 等依赖服务停止）。若它是唯一 DC 兼 DNS，期间域内会有短暂影响，建议低峰操作；停止后**立即** `net start ntds` 拉起，并补启依赖：
> `net start kdc` / `net start dns` / `net start "Intersite Messaging"` / `net start "DFS Replication"`。

#### 步骤 4：验证 636 是否起来

```cmd
:: 域控本机确认监听
netstat -ano | findstr :636
```

```bash
# 平台服务器上确认 TLS 能握手（用 DC 的 IP 即可，平台不强制主机名匹配）
openssl s_client -connect <域控IP>:636 -brief
```

- 能握手出证书 → 成功；
- 出现 `write:errno=104` / `Connection reset by peer` → 证书仍未生效，回到步骤 2/3 检查（最常见：模板没选对、没私钥、没重启 NTDS）。

> 决定性排查：在**域控本机** `openssl s_client -connect localhost:636 -brief`：
> - 本机也 reset → DC 确实没证书（证书问题）；
> - 本机正常、远程 reset → 平台到该域控的 636 被网络/防火墙拦截（网络问题）。

### 5.3 平台侧域配置填写

| 字段 | 填写 |
|---|---|
| 主机(host) | **域控 IP**（用 IP 可绕过 DNS 解析问题；用 FQDN 需服务器能解析） |
| 端口 | **636**（创建/改密码必须） |
| SSL | **开启** |
| Base DN | 如 `DC=adserver,DC=com`（连通测试会自动带出） |
| 绑定账号 | 见 6.2（建议用委派最小权限的服务账号，**不要**域管理员） |
| CA 证书 | 可选。导入该域根 CA 证书后，平台会显示证书信任/到期状态；不导入平台自动降级为不校验（不影响连接） |

保存后点「连通测试」确认。

## 6. 平台域配置填写说明（含双层权限模型）

### 6.1 平台账号（第一层：门卫）

- 平台自身的账号体系（`admin_user` 表），分四角色：超级管理员 / 管理员 / 用户 / 审计员，外加 `admin_scope` 作用域授权。
- 决定“**谁能在平台提交什么动作**”。越权或不在作用域内的请求，根本到不了 AD。

### 6.2 绑定域账号（第二层：执行者）

- 域配置里的“绑定账号密码”是**域用户**（最好用专用于平台的、在 AD 里**委派了最小权限**的服务账号，如 `svc-domaintool`），**不要**直接用 Domain Administrator。
- 平台后端拿这个账号去 `bind` 域控执行操作，AD 再按**它自己的权限**放行。
- 流程：**平台账号先过 RBAC+作用域 → 通过后用绑定账号以它的身份提交 → AD 按绑定账号权限查一道**。两层都过才成功。
- 举例：管理员在平台有权限提交“重置密码”，但绑定账号没被委派重置密码权限 → AD 返回权限不足，操作失败；反之绑定账号权限大但平台作用域没授权 → 请求到不了 AD。

> 最小权限做法：在 AD 用「委派控制向导」对目标 OU 仅授予需要的权限（创建/删除用户对象、重置密码、修改组成员、读写常规属性等），而非给全域管理员。

### 6.3 CA 认证开关（本次需求）

- 仅**超级管理员**可操作（接口 `PUT /domains/{id}/ca-mode` 用 `require_superuser` 保护）。
- **开启（ca_enabled=True）**：与现状一致——按 `cert_trust` 校验，证书不通过时限制非超管写操作。
- **关闭（ca_enabled=False）**：不启用任何 CA 限制，管理员可自由操作（`scheduler` 也只处理启用了 CA 的域）。

## 7. 增量更新部署

只改动目录覆盖后重建对应服务即可，无需整包重传。

```powershell
# 本地（项目根）
tar -czf patch.tar.gz --exclude='__pycache__' --exclude='*.pyc' backend/app frontend/src
scp patch.tar.gz user@<平台服务器IP>:/opt/DomainToolBS/
```

```bash
# 服务器
cd /opt/DomainToolBS && tar -xzf patch.tar.gz
docker compose up -d --build backend frontend
# 后端重启会自动跑 _migrate() 加新列，观察日志确认无迁移报错
```

> 临时包（如 `patch.tar.gz` / `deploy.tar.gz`）解压后可直接删，仅是传输用。

## 8. 常见问题速查表

| 现象 | 原因 | 解决 |
|---|---|---|
| `permission denied ... /var/run/docker.sock` | 用户不在 docker 组 | `sudo usermod -aG docker $USER` 后重登；或临时加 `sudo` |
| `docker run hello-world` 卡住/超时 | Docker Hub 国内不通 | 配 `/etc/docker/daemon.json` 加速器后 `restart docker` |
| `scp: dest open ... Failure` | `/opt` 无写权限或目录不存在 | 先传到家目录，再 `sudo mv`；或 `sudo chown $USER:$USER /opt/DomainToolBS` |
| 创建用户“成功但报错” | 用的 389 明文，AD 拒绝设密码（`unicodePwd` 需加密通道） | 改用 **636 + SSL 开** |
| 636 连接 `errno=104` / `Connection reset by peer` | 域控无服务器证书，TLS 握手被重置 | 装 AD CS → 申请“域控制器”证书 → 重启 NTDS |
| 申请证书时**没有“域控制器”模板** | 未安装 AD CS 角色 | 先在域内安装 AD CS（企业根 CA）并重启，模板才会出现 |
| `net stop ntds && net start ntds` 报 `&&` 不是有效分隔符 | Windows PowerShell 5.1 不支持 `&&` | 拆成两条命令分别执行 |
| 添加用户报 `ENTRY_EXISTS` | sAMAccountName 已存在 | 换未占用的登录名 |
| 审计日志时间比实际慢 8 小时 | 后端存 UTC、前端误当本地时间解析 | 已修复 `frontend/src/utils/datetime.ts`（无时区后缀按 UTC 解析）；更新前端后强刷页面 |
| 完成配置改 636 后仍报 `ssl wrapping error` | DC 证书未生效/未重启 NTDS | 确认证书含私钥+服务器身份验证，并 `net stop/start ntds` |
